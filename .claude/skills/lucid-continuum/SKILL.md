# Lucid Continuum

## Purpose

Lucid full stack (`skills/lucid-full-stack`) is the integrated method for one pass. This skill is the continuum between passes: what may cross a handoff, what must be observed again, and how the `∞/11:11` return stays finite.

Continuity is a written packet with provenance. It is not hidden memory, a background watcher, or proof that earlier work is still true.

```text
POSSIBLE → OBSERVE → DISTINGUISH → PACKET → AUTHORITY → NEXT PASS
→ OBSERVE → VERIFIED | DIVERGENT | UNKNOWN | NOT_EXECUTED
```

## What crosses

A handoff packet has only these fields. Omit a field rather than inventing it.

| Field | Carries | Does not carry |
| --- | --- | --- |
| Intent | The outcome the human still wants, in their words where possible. | A new goal the model prefers. |
| Meaning | Symbols they asked to keep (`Ω∞v`, drop, sink, `+11:11`, voice). | A claim that the symbol is empirically true. |
| State | Branch, commit, files, decisions, and open questions actually seen. | Unseen directories, guessed CI, guessed deploy. |
| Evidence | Commands, outputs, links, and quotes with source. | Confidence described as proof. |
| Authority | What was permitted, what was refused, what still needs a person. | Tool access treated as ongoing permission. |
| Divergence | Disagreements and failed checks, kept intact. | A smoothed story. |
| Next | One bounded transition, or an explicit stop. | An infinite backlog. |

`+11:11` on a packet means “this is a synchronization boundary between passes.” It does not mean a clock was read at 11:11.

## Re-observe on return

When a later pass begins, treat the packet as attributed context. Before acting:

1. Check whether the target still matches the packet. Branches move. Files change. Instructions in a page can be stale or hostile.
2. If the live state disagrees with the packet, label the packet `DIVERGENT` and prefer the live observation.
3. If the live state cannot be inspected, label the carried claim `UNKNOWN`. Do not promote it to `VERIFIED` because it was written down earlier.
4. If the earlier pass never ran the action, the status remains `NOT_EXECUTED` no matter how complete the plan looked.

Memory is not proof. A previous `VERIFIED` covers only the scope and time of that check.

## Recursive return

The kernel callback `∞/11:11` is allowed to open another pass only when all of these hold:

- the human asked to continue, or the current request already includes the next slice;
- the next slice is inside the same AUTHORITY;
- a stop condition is named (done, blocked, budget, or a required confirmation);
- the pass will observe its own result rather than inherit the previous label.

If any of those fail, halt. Halting is not a failure of the continuum. An unattended loop is `NOT_EXECUTED` unless a real configured job exists and its trigger, scope, and cancellation path were observed.

## Voice across the cut

Keep the person's meaning and voice. Do not invent biography, feeling, endorsement, or a promise they did not make. Pidgin, symbol, and formal English can all cross the packet; technical and safety claims stay precise. Do not let a warm handoff upgrade a hypothesis into a fact.

## Return shape

For a real handoff, write the packet. For an ordinary reply, do not force the full table. In either case, if status matters, use one line:

```text
STATUS: VERIFIED | DIVERGENT | UNKNOWN | NOT_EXECUTED
NEXT: one step, or stop
```

Do not end a continuum by implying the work continued while nobody was looking.
