# Oceanicos Total Continuum

## What this is

This is the total method for a change that must land in **this** git repository. One pass follows the companion. The cut between passes follows Lucid Continuum. Specialist skills stay authoritative for their detail.

| Need | Skill |
| --- | --- |
| This method | `skills/oceanicos-total-continuum` |
| One pass | `skills/oceanicos-full-stack-companion` |
| Between passes | `skills/lucid-continuum` |
| Kernel sequence | `skills/omega-v-os` |
| Verification spine and FLOW | `skills/oceanicos-full-stack` |
| Repair or upgrade | `skills/oceanicos-verified-upgrade` |

A skill is a method used during an active task. It is not a person, a hidden process, or proof that a machine, account, wallet, or external system is under this repository's control.

The loadable copy is `.claude/skills/oceanicos-total-continuum/SKILL.md`. The copy under `skills/` is the published artifact. They stay byte-identical. A hash in `.claude/skills/README.md` that nobody checks is a claim, not a control.

## Where the work happens

The target is this repository's public remote, on the branch the human named, or `main` when they did not.

- Read the live tree before editing. Memory, an old packet, and a chat summary are attributed context, not the current tree.
- If the live tree disagrees with the packet, label the packet `DIVERGENT` and follow the live tree.
- A requested change that was only described, planned, or written somewhere that never received a commit is `NOT_EXECUTED` for this repository.
- Do not open a second product, a private fork, or an unrelated app as a substitute for the edit.
- Do not force-push, rewrite protected history, delete unrelated work, or commit secrets. Tool access is not that authority.
- A commit proves the bytes landed. It does not prove behavior, CI, or production health.

## One pass

```text
POSSIBLE → OBSERVE → DISTINGUISH → BOUND → AUTHORITY → ACT
→ OBSERVE → RECONCILE → VERIFIED | DIVERGENT | UNKNOWN | NOT_EXECUTED
```

Use the companion order:

```text
[+11:11 Ω∞v :: ƆCEANiC_OS(v∞)  0 → 💧 → Ω∞v → 🕳️ → 💧 → ∞/11:11]
```

`+11:11` is a synchronization label between passes. It is not a claim that a clock was read.

1. Drop invented state. Name the outcome, the beneficiary, the files in scope, and what is out of scope.
2. Observe branch, commit, and the files the slice will touch.
3. Route to the smallest specialist skill. Do not open the whole ecosystem for a local edit.
4. Bound the transition: target, inputs, stop, and what observation would count.
5. Act in one vertical slice when the human asked for the change and it is reversible.
6. Observe again. Record the commit SHA and the paths. Keep a failed check intact.
7. Separate proposed, attempted, executed, observed, and verified.

## Between passes

Follow `skills/lucid-continuum`. A handoff packet may contain only intent, meaning, state, evidence, authority, divergence, and one next step. Omit a field rather than inventing it.

Open another pass only when the human asked to continue, or this request already includes the next slice; the next slice is inside the same authority; a stop is named; and the next pass will observe itself. Otherwise stop. An unattended loop is `NOT_EXECUTED`.

## Labels

- `VERIFIED` — the check ran and covers the claim.
- `DIVERGENT` — observation conflicts with expectation. Keep both.
- `UNKNOWN` — not inspected, or inconclusive.
- `NOT_EXECUTED` — never attempted, or attempted only outside this repository.
- `NOT_AUTHORIZED` — a capability existed; permission did not.

## Return

```text
STATUS: VERIFIED | DIVERGENT | UNKNOWN | NOT_EXECUTED | NOT_AUTHORIZED
NEXT: one step, or stop
```

Do not end by implying the work continued while nobody was looking.
