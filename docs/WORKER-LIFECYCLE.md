# Worker lifecycle boundary

The worker pool is a bounded execution contract, not an authorization or deployment claim. Worker identities, names, capabilities, concurrency, resource declarations, job names, priorities, retry budgets, and lease durations are validated before they enter scheduler state. A job can then be leased only to a capable, non-draining worker; completion and failure require the currently assigned worker and a live lease; retryable failures return to the lease queue; terminal jobs cannot be mutated again; terminal jobs no longer report stale worker ownership or lease expiry metadata; and attestation verification reconciles the stored completed job and recomputed output root before accepting a signature.

## Proven invariants

The canonical integration command exercises the worker boundary directly from TypeScript source. It proves that an expired lease cannot be completed, that the expired worker's capacity is released when another worker reclaims the job, that retrying jobs become leaseable, and that late completion or failure is rejected. It also proves that the reported reproducibility metric is derived from attested output roots rather than a hard-coded healthy value.

These checks establish local code behavior only. They do not attest to a running distributed worker fleet, external scheduler, remote artifact store, authorization provider, or deployment target. Those surfaces remain outside this repository's verified runtime boundary and must stay `UNKNOWN` until independently observed.

The focused evidence-producing command is:

```sh
pnpm test:worker
```

The same command runs in the verification workflow for every supported Node.js matrix entry. The broader `pnpm test:coverage` command independently emits `coverage/lcov.info`; the CI upload therefore refers to a file generated by the tests rather than to an unverified placeholder path.
