this ecosystem. Compressed, it is five habits —

1. **Look before you claim.** Observe, distinguish, then speak.
2. **Bound before you build.** One finite Δ, named inputs, named stop.
3. **Ask before you act.** Human authority gates anything consequential.

5. **Remember before you move on.** Carry the history of the whole into the next step, and
   keep the unresolved parts unresolved.

The blueprints also carry an unmistakable *aesthetic* mood — a luminous body inside a dark
ocean, connected by filaments of light. §10 compiles that aesthetic into the repository's

## §11 — The recursive self-reconstruction engine, in this repository

The blueprint's cycle, executed with real commands:

```text
DISCOVER → REMEMBER → RECONSTRUCT → CONNECT → COMPARE → RECONCILE
→ PRIORITIZE → AUTHORIZE → IMPLEMENT → TEST → VERIFY → DOCUMENT → LEARN → BECOME
```

| Step | Concrete action |
| --- | --- |
| DISCOVER | Read the repository before editing: `git status`, the touched contracts, `docs/REPO_INVENTORY.md` |
| REMEMBER | `node bin/oceanicos.mjs events`, ledger tip via `GET /v1/block/tip` |
| RECONSTRUCT / CONNECT | `docs/DEPENDENCY_MAP.md`, `GET /v1/dependencies`, `GET /v1/ecosystem/body` |
| COMPARE / RECONCILE | `GET /v1/reality/status`, divergences feed |
| PRIORITIZE | `Δ*` ordering by verified value, risk, cost, ε |
| AUTHORIZE | `POST /v1/omega/commands/:id/admit` then `/approve` |
| IMPLEMENT | smallest reversible change on a branch |
| TEST / VERIFY | the tests covering the change, run whole; then observation of the running stack |
| DOCUMENT / LEARN | `docs/upgrades/*`, provenance record |
| BECOME | continuity record + next bounded transition |

`REVIEW` does not execute. `NOT_EXECUTED` is a legitimate outcome of this engine, and
"no code change was appropriate" is a valid pass when the evidence says so.
