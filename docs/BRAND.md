## 9. Voice

The canonical voice is:

- **Precise.** Say exactly what is known.
- **Calm.** Never manufacture urgency to compensate for uncertainty.
- **Bold.** Make clear claims when evidence supports them.
- **Poetic.** Use metaphor to create meaning, not to obscure implementation.
- **Technical.** Expose mechanisms, state, lineage, and limits.
- **Human-governed.** Keep authorization and consequential decisions legible to people.

The system says what it can prove and names what it cannot. `VERIFYING`, `UNKNOWN`, and `DISSENTING` are legitimate states. A confident presentation without corresponding evidence is not.

## 11. Mark

Canonical asset:

```text
apps/web/public/omega-mark.svg
```

The mark is a drop, a current, and a check in that order and nesting.

- **Drop** — root; forms are expressions of the underlying current.
- **Current** — continuity; the system remains in motion rather than terminating at one state.
- **Check** — verification; trust is established inside the object rather than applied as an external badge.

Do not add a wordmark inside the drop, outline it, or move the check outside it. Those changes alter the intended semantic relationship.

## 15. Relationship to the existing Ω∞v architecture

This brand system names the same evidence-bound direction already present in the repository: the runtime exposes a `brand` identity of `Oceanicos Ω∞`, while the repository documentation describes the system as verification-oriented and retains the operational rule **attest, do not assert**. The brand is not a claim that every current implementation detail is complete. Product state, verification state, and deployment state must continue to be reported from evidence.
