# Audit: inspect-2026-10-01

WHAT I OBSERVED

- The repository is a verification-first monorepo with apps/api and apps/web, multiple packages, and documentation expressing the intended verification loop.
- Runtime code (apps/api/src/index.ts) defaults API_PORT to 5000 when not provided and sets NODE_ENV default behavior accordingly.
- The apps/README.md documents the API as starting on port 3000 while the implementation uses 5000 by default. This is a documentation vs implementation mismatch that could cause developer confusion and test failures.
- The repository contains an attestation capability; however the API's /v1/attest currently uses an HMAC-SHA256 path in code (AttestationService with algorithm HMAC-SHA256), while documentation and some higher-level claims reference Ed25519 capability. Both capabilities exist in the codebase, but it is not correct to claim all attestations are Ed25519.

```typescript
export const app = createApp(process.env.OMEGA_DB_PATH ?? './oceanicos.db', process.env.NODE_ENV !== 'test');

const start = async () => {
  try {
    const port = Number(process.env.PORT ?? process.env.API_PORT ?? 5000);
    if (!Number.isInteger(port) || port < 1 || port > 65535) throw new Error(`Invalid API port: ${String(process.env.PORT ?? process.env.API_PORT)}`);
    await app.listen({ port, host: '0.0.0.0' });
    console.log(`Fastify API listening on http://0.0.0.0:${port}`);
  } catch (err) {
    app.log.error(err);
    process.exit(1);
  }
};
```
