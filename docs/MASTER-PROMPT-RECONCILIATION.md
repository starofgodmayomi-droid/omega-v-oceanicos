## OceanicOS product prompt (2026-10-21)

The product prompt is a target for conversation, planning, governed execution, and evidence. It is not a runtime authority engine and it does not change executable behavior by being present.

| Product concern | Existing repository surface | Boundary |
|---|---|---|
| Conversation | apps/web and API surfaces already in the tree | A dashboard is not a model-backed assistant. No conversation contract is created by this document. |
| Planning | packages/mini compile and pipeline | A pipeline plan is not a user task workspace |
| Authority | admission modules and connector admission work | Client-supplied booleans are not authority. Open admission pull requests are not merged production wiring. |
| Verification | observer, verification, remember, MINI | These do not verify arbitrary external claims |
| Task and evidence UI | apps/web | The three workspaces are a target, not a shipped product surface |
| Delegation | bounded worker contracts | A local job record is not a worker network |
| External tools | connector routes | Capability is not authority. This preview and this document call no external tool. |

Lifecycle that must stay visible when a product surface is built later:

Receive → Understand → Clarify or plan → Authorize → Execute only if admitted, otherwise explain the block → Observe → Reconcile → Record → Report.

Result words that must not be collapsed: verified, partially verified, unverified, failed, blocked, cancelled.
